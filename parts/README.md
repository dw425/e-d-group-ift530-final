# The script, section by section

`IFT530_EDGroup_FinalProject.sql` is the submitted deliverable and is
assembled from these files by `tools/assemble.py`. **Never edit the
combined `.sql` directly** — an edit there is lost on the next assemble.
Edit the section, then re-assemble.

They are numbered in run order, and the order matters: tables are created
parent-first so every foreign key points at something that already exists.

| File | Section | What it does |
|---|---|---|
| `00_header.sql` | — | The header block the course requires — both members, the group, the course, the server, the OS and the date — plus the file banner describing the design. |
| `10_database.sql` | 1 | `CREATE DATABASE E_D_Group`, only when it is missing. Never dropped — dropping one needs every other connection closed first, which a script cannot guarantee. |
| `20_drop.sql` | 2 | Drops every object child-first, so the script is re-runnable. This is where re-runnability actually lives. |
| `30_tables.sql` | 3 | The ten `CREATE TABLE` statements with named `PK_`, `FK_`, `UQ_`, `CK_` and default constraints, and the six nonclustered indexes. **40 marks.** |
| `40_populate.sql` | 4 | The load: 10 rows per dimension, 48 / 30 / 23 in the fact tables. Generated by `tools/gendata.py`, never hand-typed. **20 marks.** |
| `50_func_proc.sql` | 5 | `fnGeoDistanceKm`, a scalar UDF returning great-circle distance, and `spMonthlyActiveUsers`, which validates its parameters and `THROW`s 50001 on bad input. Both with drop scripts. **20 marks.** |
| `60_views.sql` | 6 | The three views — `vwDailyActiveUsers`, `vwFreeVsPaidValue`, `vwSuspiciousTransactions`. Each joins two or more tables and each restricts with a `WHERE`. **30 marks.** |
| `70_audit.sql` | 7 | `DimPlanAudit` and the `AFTER INSERT, UPDATE, DELETE` trigger that writes it, with `ChangedAt` recording when the change happened, plus the script that tests all three operations. **20 marks.** |
| `80_cursor.sql` | 8 | `curLevelDifficulty`, declared `GLOBAL` so `DECLARE` and `DEALLOCATE` are genuinely separate create and drop statements. **10 marks.** |
| `90_tests.sql` | 9 | Thirteen tests reporting `PASS`/`FAIL`, including one that asserts the fact tables sit inside the required 20–50 rows. |

## The three views, and why each is useful

**`vwDailyActiveUsers`** — daily active users split free against paid, with
a rolling 30-day active count beside each day. Joins `FactUserEvent` to
`DimUser` to `DimAccount` to `DimPlan`; restricted to session-start events
inside the reporting window. DAU is the single most-watched number in
live-ops, and it means nothing without the trend next to it.

**`vwFreeVsPaidValue`** — sessions, events, revenue and revenue per account
by plan. Joins `DimAccount` to `DimPlan` to both fact tables; restricted to
open accounts. It answers whether paying players actually play more or
merely pay, which is what tier pricing turns on.

**`vwSuspiciousTransactions`** — payments worth a second look, with the
reason spelled out. Joins `FactPayment` to `DimAccount` to `DimUser` to
`DimGeography` twice, and calls `fnGeoDistanceKm`; restricted to payments
that fail at least one of three tests. It catches a payment from a country
the player never registered in, a payment from a high-risk location, and a
payment too far from where the player was minutes ago to be a trip anybody
took.
